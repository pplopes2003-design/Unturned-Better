# Ciclo de candidato de release — 2026-11-04

Branch: `feature/release-candidate-cycle-2026-11-04` (base: `feature/integrated-friends-host`). **Não mesclar em main**: main é o jogo-base. Não distribuir release antes de compilar e testar.

## Implementado neste ciclo

- Menu **Jogar > Hospedar amigos**: campo `Workshop IDs` com até 64 IDs publicados (separados por vírgula, ponto-e-vírgula ou espaço), deduplicação e rejeição de zero, lixo ou IDs inválidos.
- Ao iniciar, se a lista estiver preenchida, o launcher grava `Servers/UnturnedBetterFriends/WorkshopDownloadConfig.json` **no diretório da build dedicada selecionada**, usando o formato `WorkshopDownloadConfig` nativo. A lista `File_IDs` seleciona as entradas raiz; o sistema nativo de download consulta os itens filhos/dependências, exceto os que estejam configurados para ignorar. Isso **não garante** que todos os autores tenham declarado dependências corretamente.
- Se o campo estiver vazio, o launcher **não altera** o manifesto Workshop existente. O arquivo de manifesto não é apagado ao encerrar, logo uma seleção anterior persiste até ser substituída. Para zerar manualmente, feche o servidor e revise o JSON, mantendo backup.
- A seleção é destinada a conteúdo autorizado da Workshop. Os IDs não são caminhos de arquivos nem instruções executáveis.

## Revisão de integração do candidato (4 de novembro de 2026)

- **Corrigido:** a gravação inicial da Workshop usava `JsonUtility.ToJson` em `WorkshopDownloadConfig`, que não está anotada como objeto serializável no Unity. O launcher agora escreve JSON com `File_IDs` e `Ignore_Children_File_IDs` diretamente, preservando os IDs publicados como inteiros numéricos, e substitui o arquivo existente com `File.Replace` + backup. A configuração padrão restante é responsabilidade da desserialização nativa.
- **Implementado, não testado:** `MobileNPCCorpseLootJournal` armazena em disco drops recusados com retentativas limitadas após despawn/reinício. Ainda existe uma janela de perda entre remover o registro e criar o objeto nativo; a garantia é de melhor esforço, **não** transação perfeita.
- **Revisado, não testado:** grupos salvos usam ID + papel + facção para mapear seu runtime, a âncora de base não deve oscilar durante restauração e falha de reassociação resulta em restore pendente.
- **Revisado, não testado:** observações de portais não devem expulsar passagens confirmadas; rádios podem recuperar sua inscrição após transição; NPCs estacionários utilizam heartbeat de snapshots a cada 1,4 s, mantendo 0,35 s para eventos/movimento.
- **Metadados multiplayer otimizados, não testados:** cache de nome, semente e roupa por conexão e NPC, com refresh de segurança de 12 s e limpeza na saída do alcance. Buffers temporários no cliente recuperam mensagens confiáveis recebidas antes do primeiro snapshot. Detalhes em `docs/MULTIPLAYER_METADATA_REPLICATION_QA_2026_11_04.md`.
- **Teste de compilação e integração ainda indispensável:** servidor dedicado e cliente devem ser compilados da MESMA revisão da branch. Os testes NUnit foram escritos mas não foram executados nesta sessão; não houve teste de Steam nem medição de banda.
- **Atenção:** o campo de IDs não faz seleção visual nem verifica automaticamente licença, conteúdo local do cliente ou dependências não declaradas pelo autor. Se o campo ficar vazio, o manifesto existente continua em vigor.

## Riscos conhecidos

O novo campo Workshop grava o manifesto **antes** de iniciar o processo; se o processo falhar, o manifesto ficará salvo. Isso permite diagnóstico sem ocultar o estado. A declaração de dependências vem de metadados Steam fornecidos pelos autores dos itens. Código fonte revisado não equivale a build compilada.
