# Linha 2 — Registro de correções CI/GitHub (2026-11-07)

## Contexto

A linha ativa é `line2/modpack-framework`; `main` / Linha 1 permanece congelada e **não será alterada para perseguir erros antigos de GitHub Actions**. A pipeline ativa usa `windows-latest` e Python 3.11, em `.github/workflows/line2-python.yml`. Os testes C# do Steam não rodam nessa pipeline, porque os assemblies e runtime do jogo precisam estar presentes.

## Problemas encontrados e corrigidos

1. **Fixtures com barras escapadas duplamente:** `ModpackManager/test_legendary_items.py` criava falsas entradas `Type Spawn\\nID 346` e `Type Effect\\nID 991`, com barra literal, impedindo o parser de reconhecer `ID`. Corrigido para a representação de nova linha correta no código-fonte Python. Esses casos afetam `test_washington_root_attaches_with_low_weight` e `test_detect_local_burner_visual_effect`.
2. **Mensagens do Modpack Manager:** `gui.py` continha sequências `\\n` que eram mostradas literalmente ao usuário nas caixas de diálogo, dificultando diagnóstico e instalação. Normalizadas para novas linhas.
3. **Erros históricos:** a Linha 1 apresentou erros de build Unity e as primeiras pipelines tinham matrix Linux/Windows. A Linha 1 foi pausada e **não está recebendo alterações**; esses erros não demonstram falha na Linha 2.

## Como verificar todos os testes Windows em um comando

Na raiz `Line2-Modpack`:

```powershell
python -m compileall -q .
python .\run_tests.py AIService
python .\run_tests.py ModpackManager
```

Os relatórios são escritos em `Line2-Modpack/test-results/AIService-unittest.txt` e `ModpackManager-unittest.txt`.

No GitHub, abrir **Actions → Line 2 Windows Python checks**, e consultar o job `windows-python`, passos `Compile Python files`, `Test AI Service`, `Test Modpack Manager`. Há um artefato `line2-windows-test-results` anexado ao job, se disponível.

## O que ainda não foi confirmado

A ferramenta conectada não ofereceu acesso ao histórico completo dos últimos workflow runs da branch; a consulta ao commit testado retornou uma lista vazia porque só considera certas execuções associadas a pull requests. Portanto, os commits de correção **foram enviados, mas não há prova de pipeline verde** neste registro. Se o novo job falhar, a linha específica do erro de `ModpackManager-unittest.txt` ou `AIService-unittest.txt` é a evidência necessária.

A compilação de `ClientModule/Unturned2.Line2.Probe.csproj`, o menu F7, o diagnóstico F6 e o controle real de NPCs são verificações separadas que exigem o SDK .NET e assemblies Steam instalados no Windows. Ainda não foram validados no computador do usuário.

## Diagnóstico mais claro no próprio Actions

O workflow `.github/workflows/line2-python.yml` ganhou o passo `Print concise test failure details` com `if: always()`, que imprime os últimos trechos relevantes dos dois relatórios de testes e os acrescenta ao **Summary** do job. Ele não ignora erros: os testes continuam retornando código de saída não zero e o job permanece marcado como falha quando necessário.

A inclusão desse passo por commit deve disparar uma nova execução da pipeline (se GitHub Actions estiver habilitado), mas o status final ainda precisa ser consultado no GitHub.
